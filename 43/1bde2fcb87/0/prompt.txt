## Feature A

### 1. `docker/runpod/handler.py` job input contract
Keys read by `handler(event)` (1240):
- **Audio:** `audio_url` (a GET URL, fetched with urllib, 1252/1283-1291) or `audio_base64` (1251). One of the two is required (1253).
- **`mode`:** `"demucs"`, `"whisper"` or `"both"`, default `"both"`. Any other value raises `ValueError` (1260-1262).
- **`align_text`** (str, 1267) and **`align_lang`** (ISO-639-3, default `"eng"`, 1270).
- **`whisper_lang`** (ISO-639-1, lowercased; empty means auto-detect, 1276-1280).
- **`vocals_put_url` / `instrumental_put_url`:** presigned PUT URLs. The upload path is used only when both are present (1303-1305).
- **`job_budget_s`:** used only for the retry deadline in "both" (1345).
- Nothing else is read.

**Alignment runs only if separation runs.** `want_align = bool(align_text…) and mode in ("demucs","both")` (1281), and alignment also needs `vocals_path is not None` (1336). So `mode="whisper"` never aligns.

**What `mode="whisper"` does:** it does not separate. It transcribes the input file directly: `target = vocals_path if mode == "both" else in_wav` (1330).

**Feasibility on an already-separated stem, without handler changes:**
- **Whisper only:** feasible. Send vocals.wav with `mode="whisper"`.
- **Forced alignment:** not possible without separation. `mode="demucs"`/`"both"` re-runs BS-Roformer on the input (1317-1319). Running it on vocals.wav would probably still work, but it costs a full separation.
- An "align-only / skip-separation" mode needs a handler change. The seam is 1281 and 1336: let `vocals_path = in_wav` when a new flag or mode is set.

**Result dict** (1307-1368):
- Separation modes: `vocals_uploaded`/`instrumental_uploaded: True` on the PUT path, otherwise `vocals_b64`/`instrumental_b64` inline (1320-1327).
- Whisper modes: `lyrics_txt`, `lyrics_json` (1333-1334).
- When alignment ran: `aligned_lrc`, `aligned_lang`, `aligned_line_scores` (1356-1357, only if the LRC is non-empty), `aligned_raw_lrc` (1363), and always `aligned_diagnostics` (1364, schema_version 1 with `lines`/`retries`, plus `alignment_error`/`retry_error`).
- Always: `gpu_model`, `elapsed_s`.
- All text is returned inline in the RunPod output JSON (~10 MB cap). Only the WAV stems go out through the R2 presigned PUTs (`_put_file`, 1220).
- The docstring (12-51) is out of date: it does not list `audio_url`, the put URLs or `whisper_lang`.

### 2. `src/karaoke/worker/runpod_client.py`
- **`RunpodClient.__init__(settings, *, prior_24h_cost_micros=0, http=None, r2_uploader=None)`** (175). The `http` and `r2_uploader` arguments are test seams.
- **`run(mix_wav, work_dir, *, align_text=None, align_lang=None, whisper_lang=None) -&gt; GpuJobResult`** (211):
  1. `_check_daily_cap()` runs before any HTTP call (238).
  2. If R2 is configured (`_r2_configured`, 414), `_upload_to_r2` (422) uploads to key `jobs/{ts}-{uuid12}/mix.wav`, presigns a GET, and presigns PUTs for `…/vocals.wav` and `…/instrumental.wav` (442-476). `run_input = {"audio_url", "mode": "both", vocals_put_url, instrumental_put_url}` (253-258).   3. **`mode` is hard-coded to `"both"`** (255, 261).
  4. It then adds `align_text`/`align_lang` (265-268), `job_budget_s = min(wall_ceiling, max_job_cost/rate*3600)` (270-272) and `whisper_lang` (275-276).
  5. `POST /run`, then polls `/status/{id}` every `runpod_poll_interval_s` (319-390). A queue ceiling raises `RunpodCapacityError`/`RunpodColdStartError`; a wall backstop raises `RunpodTimeoutError`; the per-job cost check runs before each poll (348-357). The `finally` cancels any non-terminal job (391-403).
- **`_materialise`** (533):
  - Requires `lyrics_txt` and `lyrics_json`, otherwise raises (542-547).

  - Writes into `work_dir`: `vocals.wav`, `instrumental.wav`, `lyrics.txt`, `lyrics.json`, and optionally `aligned.scores.json`, `aligned.lrc`, `aligned.raw.lrc`, `aligned.diagnostics.json` (549-590).

- **`GpuJobResult`** (`vast_client.py:70-85`): `vast_instance_id`, `vast_cost`, `gpu_model`, `vocals_path`, `instrumental_path`, `lyrics_txt_path`, `lyrics_json_path`, `aligned_lrc_path=None`, `aligned_raw_lrc_path=None`, `aligned_diagnostics_path=None`.
- **Passing vocals.wav plus a different mode is not feasible without client changes**, for three reasons: the mode is hard-coded, stems are required in `_materialise`, and the handler cannot align without separating. Sending vocals.wav as `mix_wav` with mode "both" works today, at the cost of a second separation.
- **`_run_gpu_with_capacity_retry(session_factory, job_id, settings, client, mix_wav, work_dir, *, align_text, align_lang, whisper_lang=None)`** (`pipeline.py:1394`):

  - It mutates `Job.status`, so a lyrics-only re-run through it would flip a completed job back to `transcribing`.

### 6. Job (re)start
- **Statuses:** `JobStatus` (`db/models.py:25`) is `queued, downloading, separating, transcribing, completed, failed, cancelled`. `finalizing` is WS-only and has no DB value (pipeline 1233-1241).
- **Dispatch:** `scheduler.schedule_job(session_factory, job_id, settings)` (`scheduler.py:51`) picks the mock (`api/worker_stub.schedule_mock_job`) or `pipeline.schedule_real_job` (1512), which wraps `asyncio.create_task(run_real_job(...))`. `_use_runpod` is at scheduler.py:38.
- **`run_real_job`** (1011) always runs the full pipeline: download or ffprobe the upload, `_to_wav`, canonical resolve, LRCLIB fetch, Genius, GPU (separate, transcribe, align), mp3 encode, `_resolve_lyrics`, metadata, Artifact rows, completed. It exits early if the job is cancelled or failed. Any exception goes to `_mark_failed` (449).
- **There is no retry endpoint.** Retry is purely client-side: `App.tsx:187-195` calls `createJob({url: job.source_url})`, which creates a new job and fully re-downloads. `jobStatus.ts:127-138` `canRetry`/`canRetryJob` limits this to failed/cancelled URL jobs and excludes `upload://`.
- **There is no lyrics-only stage or re-run path.**
- **Reusable seam:** `_resolve_lyrics(lyrics: LyricsResult, exports_dir, whisper_lyrics_txt, aligned_lrc_path=None, whisper_lyrics_json=None, *, second_text=None, lang=None)` (`pipeline.py:487`) is a pure function of files already in `work/`. It calls `_select_lyrics` (595) and writes `lyrics.lrc`, `lyrics.txt` and `lyrics.quality.json`, but not `metadata.json` (1272-1339 builds that).
- `LyricsResult` is at `worker/lyrics.py:884` (`synced_lrc`, `plain`, `instrumental`, `source`, `rejected`, `rejected_text`, `match_variant`, `duration_gate`).
- Language helpers: `_script_lang_hint` (878), `_align_lang` (905).
- **Boot reconcile:** `worker/reconcile.py` (called from `app.py:54`) fails any `downloading`/`separating`/`transcribing` job on restart and re-dispatches `queued` ones. A background lyrics rebuild that reuses these statuses would be failed on redeploy.
